warmup A

Shape prior warmup: SAM3D worker 不是 per-frame loop

Demo v5.1 的 shape prior 是一次 frame-0-like 请求。主相机进程等到 第一帧 mask、depth、PCD 都齐了以后，把 RGB、object mask、用于对齐的 object observation mask、controller mask、color-aligned depth、 K 和 camera-to-world 发给 worker。worker 只需要生成一次结构先验， 写回 shape_prior/points.npz。

  • worker 启动在主相机进程之前，由 main.py 管理。
  • 默认 warmup 模式是 dual: physical GPU 1 被暴露给 worker。
  • worker 先 preload x4 upscaler 和 SAM3D inference，然后绑定 ZMQ。
  • 结果包含 combined points、surface points、interior points 和 metadata。
  • chunk writer 在写 final_data.pkl 前等待 surface/interior points。

warmup B

其他 warmup: 相机、SAM3.1、EdgeTAM、TapNext++

这条 warmup 是主 runtime 的稳定启动链。它不是 shape prior 本身， 但会决定第一批 frames.jsonl 和 prepared PhysTwin frame 什么时候 开始稳定出现。

  • 如果深度源是 FFS，先创建 TensorRT runner 并 warm up Numba align。
  • live 模式启动 RealSense；fake-live 模式启动 recording replay source。
  • SAM3.1 只在第一帧做 controller/object mask 初始化。
  • EdgeTAM 加载 HF runtime，应用 compile mode，并开始 streaming session。
  • TapNext++ 在 union/object/controller mask 上采样 query 并初始化 tracker。

actual run

当前 actual run: 右侧是 visualizer，不是 realtime_phystwin

当前默认路径

optimization_mode: disabled，所以 actual run 不会启动 realtime_phystwin/train_online_zero_then_first.py。它会启动 demo_v5_1/visualize_track.py，默认 side-by-side 布局。

左侧画面

visualizer 读取 capture dir 里的 input_frames.jsonl 和 input_rgb/*.png，显示 camera/fake-live 输入时间线。

右侧画面

visualizer 读取 online_data/<case> 与 data/<case>/final_data.pkl，显示已经发布的 object/controller/shape-prior/tracker 结果。

可选但当前不用

如果手动改成 --optimization-mode continuous，v5.1 会在第一 个 committed chunk 后先释放 managed shape-prior worker，再在 GPU 1 启动 realtime_phystwin online optimization。这不是当前默认 actual run。
