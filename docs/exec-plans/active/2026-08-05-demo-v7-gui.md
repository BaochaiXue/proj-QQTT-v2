## 定案

- **PySide6 而非 Rust**:流水线本就是 Python 子进程,Rust 只会把语言边界
  压在最高频改动的接缝(流水线控制)上;GUI 真实负载是 30Hz 贴图(Qt C++
  渲染)。效率纪律:UDS+JPEG、latest-wins、无逐像素 Python 循环。
- **进程拓扑同 6.2**:GUI+orchestrator 父进程(chunk 会话、points.npz
  触发 PhysTwin 复用 6.2);相机服务子进程(CUDA ns 同 6.2 配置)import
  复用 mdp 全部阶段。新增仅:ipc/protocol+channel、按钮驱动状态机
  (staged_runtime)、frame-0 派生管线(frame0_pipeline)、Qt 界面。
- **warmup 无追踪**(委托决定):frame-0 后场景不含摆位物体/手,EdgeTAM/
  tracker 均不启动;正式开始时以摆位后帧为"正式 frame 0",用保存的
  frame-0 SAM3.1 mask 种全新 EdgeTAM session(SegmentationStage 子类只
  覆盖 seeding,其余原码)。这是对 6.2 语义最小且自洽的改动:摆位由人
  对齐 mask 保证 prompt 语义成立。
- 状态机:STARTING→PREVIEW→FRAME0_PENDING→WARMUP→REVIEW→REPOSITION→
  FORMAL→FINISHED(+FATAL)。协议唯一事实源 demo_v7/ipc/protocol.py。
- fake-live 语义修正(owner 2026-08-05):**只 fake 来源,不 fake 相机的
  持续输入特性** —— 流永不暂停(暂停机制整体删除);拍照=抓当前帧快照;
  摆位 overlay 叠实时流;正式 frame-0 = seg 就绪时的当前帧(与 v6.2
  barrier 一致);正式前素材播完自动从头 + 状态栏提示(wrapped=True),
  正式期播完弹窗结束(wrapped=False)。
