## Echo benchmark: sparse masked_uv_depth probe

```bash
conda run --no-capture-output -n demo_2_max \
  python services/ffs_remote/ffs_depth_client.py \
  --endpoint tcp://100.66.203.123:7001 \
  --echo-benchmark \
  --profile 848x480 \

  --mask-fraction 0.06 \

```

Result:

```text
status=error
FfsRemoteProtocolError: request expected 3 parts, got 4
duration_s=20.07
sent=184
ok=0
failed=184
```

Interpretation:

```text
The currently running Ubuntu-4090 echo server is an older echo-only protocol
that accepts only metadata + left IR + right IR. It does not accept the mask
payload needed by masked_uv_depth sparse echo / real sparse remote FFS.
```

## Decision

Current synthetic echo status:

```text
TCP/protocol reachable, but synthetic full-frame echo throughput is low.
```

This is no longer the formal remote FFS pass/fail criterion. Formal handoff must
use real-IR remote-depth:

```text
WSL-5090 captures real D455 IR left/right frames.
Ubuntu-4090 runs strict TensorRT FFS.
WSL-5090 receives real depth_u16/depth_float_m.
depth_nonzero_count > 0 is required.
```

Do not use synthetic echo or zero-depth echo as professor-facing remote FFS
evidence. The next meaningful server/client sequence is:

```text
1. Ubuntu-4090 starts strict FFS server with --return depth_u16 --compress lz4.
2. WSL-5090 runs ffs_depth_client.py --real-ir-depth-benchmark.
3. Only real depth results decide remote FFS handoff.
```
